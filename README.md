# 分发工作台

独立的 Windows / macOS 图文分发客户端。以一份 Markdown 主稿为基础，维护平台独立稿，通过各账号的独立浏览器会话填充发布编辑器。内容、图片和任务保存在本机。

## 开始使用

开发环境要求 Node.js 22.12+（推荐 `nvm use`）。

```sh
npm ci
npm run dev
```

生产构建与运行：

```sh
npm run build
npm start
```

打包：

```sh
npm run dist:mac
npm run dist:win
```

产物在 `release/`。安装包暂未签名，macOS 包未公证，安装时可能出现系统安全提示。验证记录见 [自动化验证](docs/ACCEPTANCE.md)。

## 使用流程

1. 新建或导入 Markdown。导入支持首行 H1、简单 frontmatter 标题，以及文章目录及子目录中的相对图片路径。不会遍历上级目录读取文件。
2. 在主稿中整理事实和步骤，切换平台预览排版。平台稿可以独立改写；公众号自动应用内联样式，小红书需要独立短稿与配图。
3. 在平台账号页添加账号并打开官方平台窗口登录。同平台的多个账号分别使用独立会话。
4. 保存文章，点击分发，选择账号和可选预约时间。创建任务时固定内容快照；同账号相同内容不能重复创建。
5. 在平台窗口打开空白文章编辑器。客户端识别标题与正文后执行填充。平台已有其他内容时停止，不自动覆盖。
6. 检查图片、封面、标签、分类与预览，在平台完成最终发布。回工作台填写文章链接，登记“已人工确认发布”。

公众号通常需要先在后台手动新建图文；简书需要选择文集并新建文章。验证码、认证和平台审核由平台本身完成。

## 已实现

- 主稿库、分类与全文搜索，最近 30 次主稿历史、恢复与复制。
- 十个第三方平台的编辑器适配入口；自建 Web 的 HTML / Markdown 导出。
- 主稿与平台稿独立编辑、隔离预览、富文本/Markdown 复制。
- 图片按 SHA-256 去重、引用、导入、可移植分发 ZIP。
- 多账号独立持久化会话，官方页面登录和编辑器可用性检查。
- 持久化队列、预约、暂停、失败继续、重复拦截、日志和人工登记发布链接。
- 原子数据文件替换、上一次状态备份、中断恢复、完整内容备份与恢复。
- 渲染器和平台页面隔离，窄 IPC、输入校验、HTML 清洗和导航域名限制。

## 当前边界

- 自动化覆盖“填入编辑器并回读检查”；不伪装成正式发布成功。页面保存、图片转存与最终发布由用户检查。
- 小红书短稿由用户编辑，不调用 AI、不自动截断正文。其他平台按主稿或独立平台稿分发。
- 预约执行要求客户端运行。正常退出后到期的队列下次启动会执行；运行中意外中断的任务转为需要处理。
- 图片在预览中显示不等于平台已转存。远程图片可能被防盗链或跨域策略阻止，必要时使用本地图片并在平台上传。
- 当前没有云端账号托管、后台关机发布、团队权限、统计采集。

## 工程结构

```text
src/domain.ts          领域模型、平台元信息与跨进程契约
src/main.tsx           工作台界面
src/styles.css         界面样式
electron/store.ts      持久化、版本、快照、任务去重
electron/content.ts    Markdown 渲染、清洗、平台排版
electron/publisher.ts  独立会话与发布任务执行
electron/inject.ts     页面编辑器检测、冲突预检、填充回读
electron/main.ts       桌面生命周期、IPC、文件导入导出
electron/preload.ts    最小工作台桥接
```

生图请求与配置管理位于 `electron/image-api.ts` 和 `electron/image-config.ts`。第三方依赖许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

## AI 配图

已接入火山方舟、阿里云百炼、MiniMax 的文字生图。设置中配置服务，素材库中生成并插入文章；支持配置导入导出，密钥加密保存在仓库外。详见 [生图配置](docs/IMAGE-GENERATION.md)。

素材卡片支持点击放大、原始尺寸查看与删除。删除前检查主稿、平台稿、历史版本和任务快照引用；未引用的原图移至用户数据目录的 `deleted-assets/`，可通过导入图片恢复。

## 快速账号检测（2026-11-04）

账号页点击“批量快速检测全部账号”，或在本目录执行：

```sh
npm run accounts:check
```

命令把检测请求交给同一个 Electron 主进程，复用已有独立登录会话；若客户端未运行则启动客户端。无须 LLM、逐个平台点击或填写文章。升级后先重启客户端，开发时先构建主进程。

检测优先使用现有窗口的只读状态，其次使用已接入的身份接口（知乎、Bilibili），检查创作入口的登录跳转，最后在隐藏窗口等待页面加载并检测标题／正文或登录表单。并发上限 3，单账号总时限 16 秒；重复请求合并。API 403、验证码、风控、超时及无法识别均保持“暂未确认”，不会直接判定掉线。

后台检测与手动登录窗口共用浏览器兼容配置。公众号、小红书、搜狐号支持结合后台路径、账号区域和创作导航识别“已登录”，不要求先打开完整编辑器。知乎身份验证成功后继续检查编辑器；未识别到编辑器时保留已确认的身份结果。公众号首页、小红书上传入口等没有标题和正文时，不标为编辑器已验证。检测不创建文章或上传图片。

结果分别为“已登录”“编辑器已验证”“需要登录”“暂未确认”，附检测方式和时间。已登录不表示具备发文权限，编辑器识别也不等于图片上传或发布链路通过。Cookie 存在不作为有效登录证据，不读取或输出其值；结果只包含账号摘要，不包含 Token 或完整平台 URL。

命令在本机用户数据目录生成 `account-health-report.json`，用请求 ID 区分陈旧结果；命令超时返回失败。协议未授权任意 URL、任意输出路径或外部发布。平台改版后维护 `electron/account-health*.ts`，优先增加经过验证的只读接口，禁止用猜测接口替代验证。
### Bilibili 图文文章

支持添加 Bilibili 独立账号会话、主稿预览、创建分发任务，以及向官方图文编辑器填充标题和富文本正文；入口为 https://member.bilibili.com/platform/upload/text 。该通道不投稿视频。登录健康检查优先使用只读 `/x/web-interface/nav` 接口，并校验业务状态；接口登录通过不代表编辑器或投稿权限验证通过。

正式发布仍由作者在平台确认。封面、分区、标签、图片转存及平台不支持的格式需检查；不会自动开通权限、绕过验证或点击发布。当前填充通过隔离编辑器夹具验收，真实账号的编辑器兼容性仍需登录后确认。

### 账号资料表与登录快捷卡片

各平台窗口顶部有固定导航栏：后退、前进、刷新／停止、平台后台、写文章和登录资料。导航沿用当前账号独立会话，仅显示域名；写文章只打开入口，不执行填充或发布。工作台向当前页填入内容后，导航前会提醒检查是否保存；平台自身的离开页面提示也会保留。支持 `⌘[` / `⌘]`、`Alt+←` / `Alt+→` 和 `⌘R` / `Ctrl+R` 快捷键。

左侧「账号资料表」按已连接账号展示平台、账号名称、登录账号、密码、登录方式、绑定邮箱／手机号、备注和更新时间，可搜索、编辑和新增账号。密码默认隐藏，点击显示 15 秒，失焦即隐藏；账号和密码均可一键复制。复制后 30 秒仅在剪贴板仍为本次内容时清除。

从「登录 / 打开」或资料表「登录」进入平台时，会出现独立的本地登录卡片。卡片只允许读取该账号，平台网页没有资料接口；不会自动提交登录表单。关闭平台窗口会一并关闭卡片。资料更新后重新聚焦卡片即可刷新。

资料表目前仅保存在本机，不提供云同步。全部登录资料使用 Electron safeStorage（macOS 系统钥匙串等）加密，存放于用户数据目录的 `account-vault.encrypted.json`，文件权限为 0600；系统安全存储不可用时拒绝保存，不能退回明文。该文件与 workspace.json、账号检测报告和普通备份分离，普通备份不含登录资料，复制加密文件到其他电脑通常不能解密。删除平台账号同时移除其资料。
